# 网页离线运行验收

2026-09-25，使用生产构建 `dist/` 和独立本地端口，在桌面内置浏览器打开网页，等页面显示“资源缓存已完成”后停止预览服务器。随后在服务器未运行时重新加载同一页面，页面成功显示三维模型，并可切换深蹲紫色关节研究参考、卧推和实力举的 OpenSim 参考路径、Z-Anatomy 静态解剖网格。更新到缓存 v108 后再次在 390 px 视口完成停止服务器、重新加载和深蹲紫色读数卡切换；读数卡留在三维模型面板内。

这证明该浏览器的当前缓存包可在服务器停止后重新打开主要内容。它不覆盖 Android WebView 的真机离线启动、系统分享与备份导入导出，也不验证个人关节或肌肉力量。网页生产包由 `npm run build` 生成，缓存清单及静态资源可由 `npm run check:offline-cache` 复核。

发布包**装了什么、能连到哪里去**另由 `scripts/audit_shipped_package.py` + `npm run check:shipped-package-audit` 逐项审计（权限、合并清单、调试证书、外部主机、网络调用点与本机存储键），结论与限制见[隐私与本地数据](隐私与本地数据.md)。那也是静态审计，仍不能替代上面的真机验收。

页面何时可用、发布包多大，以及“资源缓存已完成”这句话凭什么可以说，见[网页启动与体积预算](网页启动与体积预算.md)：冷启动首次内容绘制 319 ms、刷新由缓存提供且传输 0 字节；Service Worker 现在逐项核对预缓存清单，缺项时界面显示“离线包未就绪 · 缺 N 项”，`npm run check:offline-cache` 会故意删掉一个资产来验证它不会谎报。

**上面这条“无网络可打开”已经不只是手记**：`npm run check:ui-offline` 在真实浏览器里加载生产构建，等离线包核对完整后用 DevTools 协议把网络关掉，再刷新并走一遍默认示意模型、深蹲／卧推／实力举三份参考数据、10.7 MB 解剖研究层与视图切换，验证 9 件事——断网刷新仍由 Service Worker 接管并启动、三份参考数据确实在 Service Worker 缓存里、**没有任何打包资源再向服务器索取**、状态栏显示“离线 · 资源缓存已完成”、恢复联网后自动退回、全程没有未捕获错误。**光有关网不够**：DevTools 的关网拦不住 Service Worker 自己的 `fetch()`，所以检查让本地测试服务器在离线包核对完整后拒绝并记录每一个请求，只有浏览器对 `/sw.js` 的更新检查、worker 对 `/` 的网络优先导航尝试和站点 `favicon.ico` 探测可以到达它。负向验证：从预缓存清单删掉 `bench_tsm_reference.json` 后，检查会在“三个动作都能在断网下加载参考数据”这一步超时失败（加固前同样的负向操作曾假通过，见[阶段总结](项目阶段总结.md) 增补之十九）。局限：仍然只是 Chromium 桌面内核，与真机飞行模式、系统省电策略、WebView 存储回收不等价，真机验收仍需要设备。
