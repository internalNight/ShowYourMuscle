2026-09-26 修正了该脚本的两处环境相关问题。其一，脚本以无 BOM 的 UTF-8 保存，Windows PowerShell 5.1 会按系统 ANSI 代码页读取 `.ps1`，使中文提示串解析失败（`Unexpected token`／`Missing closing '}'`），只有 PowerShell 7 才能直接运行；现改为带 UTF-8 BOM，5.1 与 7 均可解析。其二，`$ErrorActionPreference = 'Stop'` 下 Windows PowerShell 5.1 会把任何原生命令的 stderr 输出转成终止错误，`npm run android:sync` 只因 Vite 的包体积提示就会中止整个构建；现以 `Invoke-NativeTool` 在调用原生工具时暂时容忍 stderr 并显式检查退出码，失败信息与判据不变。本次 v110 构建是在 **Windows PowerShell 5.1 + JDK 21** 下完整跑通的首次记录。

两个源码集原先都是 Capacitor 模板残留：包名为 `com.getcapacitor.myapp`，而其中唯一的设备测试断言 `com.getcapacitor.app`，与真实 `applicationId`（`com.muscleatlas.prototype`，见 `android/app/build.gradle`）不符，任何接上真机执行都会失败。现两个源码集都移到真实包名 `com.muscleatlas.prototype`，设备测试除断言真实包名外，还新增一项**打包烟测**：打开 `assets/public/index.html`，确认它非空（大于 100 KB）且包含离线缓存令牌 `muscle-atlas-v`（只断言前缀，缓存版本升级不会让测试失败）。这项检查能抓出“改了网页但没跑 `cap sync` 就编译 APK”的情形——那种包在真机上只会显示空白 WebView。

设备侧执行需要连接手机：`gradlew :app:connectedDebugAndroidTest`。不接设备也能验证到编译与打包这一步：

```powershell
$env:JAVA_HOME='D:\Android\jdk-21.0.12.1+1'; $env:ANDROID_HOME='D:\Android\Sdk'
cd android; .\gradlew.bat :app:assembleDebugAndroidTest
```

2026-09-26 该命令执行成功（`packageDebugAndroidTest` 完成），即两个测试类的包名、断言与依赖都能正常编译打包。

同一批命令里的 `:app:testDebugUnitTest`（主机侧单元测试）在本检出**无法运行**：它对任何测试类都报 `ClassNotFoundException`，尽管测试类已编译、字节码有效（584 字节、`CAFEBABE`、class 版本 65）、所在目录 `build\intermediates\javac\debugUnitTest\compileDebugUnitTestJavaWithJavac\classes` 也确实出现在测试工作进程的 classpath 上。把测试文件换回模板原包名 `com.getcapacitor.myapp` 后同样失败（`2 tests completed, 2 failed`），因此这与本次改包名无关。可疑原因包括项目路径含非 ASCII 字符（`…\ChatGPT\人体肌肉模型`）与 AGP／Gradle 8.14.3 在 Windows 上的类加载路径处理，未继续深挖。**结论：仓库的验证体系不依赖安卓单元测试**，真机侧的防线是 instrumented 源码集；如果以后要写主机侧单元测试，必须先解决这一环境问题。
