# 已知箱重的竖直支撑力核查

## 为什么使用这组资料

[Human Data Corpus 的 INAIL Lifting Dataset 1](https://humandatacorpus.org/lifting-and-carrying-iso-11228/)公开了双手举箱的逐人三维标记点、左右脚力板和 16 路表面肌电。随包协议列出箱重：LI1、LI2 各 23 kg，LI3 为 22.09 kg；受试者表列出部分人的体重、身高。这使我们能在独立实验中核对“人体重量＋器械重量＋器械加速度”对**整体竖直地面支撑力**的解释程度。动作是搬箱，箱子由地面拿起，不是杠铃深蹲、卧推或实力举。

## 可复算方法

运行 `& '.cache/opensim-venv/Scripts/python.exe' scripts/download_inail_lifting_dataset.py --all`，从公开 ZIP 用 HTTP 字节范围只抽取 17 人 MAT 文件、受试者表和原始协议；ZIP CRC 核对通过。原始文件留在 Git 忽略的 `.cache/research/inail/`，不进入手机包。再运行 `& '.cache/opensim-venv/Scripts/python.exe' scripts/benchmark_inail_lift_support.py`，得到[逐人和逐试次 JSON](data/inail_loaded_lift_support_benchmark.json)。

文件实际含 17 人 132 个试次，少于随附说明中预期的 153。S11–S17 的体重、身高在表中为空，试次还使用了说明里未定义的 LI1S／LI2S 标签；为避免猜重量和人体质量，将这 7 人的 42 个试次排除。其余 10 人 90 次中，5 次没有有效力板、1 次动作事件无效，留下 **10 人 84 次**。排除规则只涉及输入与事件质量，不按预测误差筛选。

以公开体重 `M`、箱重 `m` 及重力加速度 9.81 m/s² 计算静态预测 `(M+m)g`。动态候选为 `(M+m)g + m·a箱`：箱体四个标记点的竖直坐标先用 6 Hz 四阶零相位低通，再以 101 采样点的三阶 Savitzky–Golay 二阶导数求加速度。为检查求导对平滑设置的敏感性，另外固定 4 Hz／131 点和 8 Hz／71 点两档；它们使用同一批合格试次，未据误差挑选。实验标记点 340 Hz；双脚竖直力板各 680 Hz，经时间插值对齐。比较公开标注的举起开始到举起结束时间段，试次 MAE 除以 `(M+m)g`；**每人试次误差的中位数**是跨人的汇总单位。公式没有从目标力板数据拟合系数。双脚力之和还与资料自带的合力列逐样本核对一致。

| 指标 | 结果 |
|---|---:|
| 合格受试者／试次 | 10 人／84 次 |
| 静态预测的跨人 MAE 中位／总重 | 0.0507 |
| 加入实测箱体加速度后的跨人 MAE 中位／总重 | 0.0383 |
| 逐人配对误差改善中位／总重 | 0.0089 |
| 动态候选优于静态的人数 | 10/10 |
| 人数优势单侧符号检验 | p = 0.00098 |

三档加速度平滑的跨人 MAE 中位／总重依次为 **0.0385**（4 Hz／131 点）、**0.0383**（6 Hz／101 点）和 **0.0384**（8 Hz／71 点）；每档均为 10/10 人优于静态基线。这个范围只针对所试的三组参数，不能替代传感器误差、动作条件或手机预设轨迹的外部验证。

举起前的双脚力板与公开体重的差值逐人中位范围约 **−57.7 至 +50.5 N**；跨人中位接近 0 N，不能掩盖个体差异。这一步只说明已知箱重及**实测箱体运动**能更好解释脚下整体反力。人体各体段质心加速度、箱子真正离地与接触时刻尚未建模，因此剩余误差不能全归因于器械轨迹。后续用同批人体标记点做了[人体运动代理探针](INAIL人体运动代理核查.md)，仍非真实质心或手机个人预测。16 路肌电虽在原始文件中，本基准未用于任何力值校准，也没有单块肌肉力真值。

## 对手机原型的影响

手机目前由用户输入体重和重量，播放的是预设动作，不会测量本人器械加速度。这里动态候选使用实验标记点，**不能把 3.8% 误差转述为手机的个人预测精度**。下一步须在匹配的杠铃动作上验证器械轨迹、人体质心、足底／凳面／双手外力，再检查关节净力矩和肌肉分担；在此之前，红色高亮仍不能表示经验证的个人肌肉发力。原数据网页未给出适合商业再分发的明确许可；当前只保留本地研究副本，不打包原始试次。
