# 检查与负向验证

一份**账**：仓库里 38 项检查各自守什么、以及**它有没有被真的破坏过**。

为什么需要它：一项检查只有"在它该守的东西被破坏时会失败"才算证据，否则只是一段会点头的代码。前几轮吃过两次亏——第 27 轮发现 `docs/安卓构建.md` 与包不一致时是靠"我记得重跑审计器"才发现的，第 32 轮直接证明 `check:shipped-package-audit` 在三种破坏下全部通过。这份账把每项检查的验证状态写在明处，"我验过了"这句话可以被对照。

**状态只有两种取值**，由 `npm run check:repo-hygiene` 强制：

- `已做（…）`：真的破坏过它守的东西并看到它失败，括号里是记录在案的地方。
- `待做`：**尚未**破坏验证。

- `check:full-body-scaling` 是这一轮为"把 OpenSim 全身模型变成默认视图"这条主线开的第一条检查，做法与其它数据类检查相同：探针 `scripts/probe_full_body_scaling.py` 在本地 OpenSim 4.6 上离线跑（Node 里跑不了 OpenSim），检查只读它写下的 `docs/data/full_body_scaling_probe.json` 并**从原始数字重算每一个比例和汇总**，所以汇总字段漂移、或者记录成"什么都没缩放"都会失败。7 项扰动全部被抓：把最高一档的股骨长度改 0.1%、把围度步进后的膝力臂改回基线值、把 +20% 的因子改成 1.05（与自己的标签不符）、把模型 SHA-256 改成 64 个 `A`（它会去磁盘重算真实哈希）、从限度清单里删掉"体脂"那一条、把肌肉数从 80 改成 40、以及把最高一档的股骨长度改成比基线更短；每次扰动都按字节还原并核对文件 SHA-256 不变。**边界**：探针本身没有被自动化重跑（本机有 OpenSim 才跑得起来），检查保证的是"记录自洽且与磁盘上的模型同源"；同目录更早的 `person_scaling_probe.json`（单腿简化模型）至今**没有**对应检查，这是已知缺口。
- `check:full-body-skeleton` 守的是**随包发布的那份骨骼文件本身**：节点树必须等于 OpenSim 模型的体段树（腿和臂是五级链，不是二十二块骨头都挂在根上）、每个体段的三角面数与顶点数要**从 GLB 的访问器重算**后与记录一致、拼装高度与宽度要落在人类骨架区间、围度映射（胸／腰／大腿／小腿／臂）指向的体段必须真实存在——映射里一个错字会让某一段静默地不再随围度变化，别的断言都发现不了。5 项扰动全部被抓，报错分别点名“the recorded triangle count is not what the GLB holds”“the recorded parent is not the parent in the GLB”“the recorded height is not the recorded bounds”“the girth map points at an unknown body: not_a_body”“the export limitations were dropped”，每次按字节还原并核对 SHA-256 不变。**边界**：GLB 二进制本身没有被逐字节校验（记录里的字节数与访问器读数会对上，但改动顶点坐标且同步更新记录不会被发现），镜像与网格替代的正确性靠的是导出时的肉眼与投影核对，不是这条检查。
- 限度：这份账记录的是"**会不会失败**"，不是"断言是否充分"。一项检查可以通过破坏验证，却只覆盖了它名字暗示的一部分——例如 `check:shipped-package-audit` 只要求文档在某处引用正确的字节数与完整 SHA-256，不要求文档里不出现别的数字。
