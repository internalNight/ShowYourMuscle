- 解释了候选模型膝伸容量曲线的非单调回升，并把上一条的右膝结论撤回为“未决”（`scripts/probe_high_flex_knee_range_validity.py` + `npm run check:high-flex-knee-range-validity`）：候选模型的髌股关节三条 `SimmSpline` 自变量节点止于 **2.0944 rad = 120.000°**（胫股关节是多项式，无限制），`vaslat_r` 力臂峰值**正好落在 120.000°**、斜率在同一处由 +0.058 翻成 −0.039 cm/deg——所以“回升”是力臂在模型数据范围内升到终点、再在数据范围外算出的形状。按帧重算（每帧自己的实测关节力矩作需求、按 120° 切开）后：**≤120° 内两个模型、两个受试者都没有任何一帧越界**（还原 0.90／0.75，候选 0.45／0.35）；AB01 的 1.47／1.40 全在 >120° 的帧里（47／22 帧越界），而那里候选模型的髌骨几何已超出自身数据范围、140° 以外连姿态都被钳制，还原模型则既没有髌骨又让腿后肌群力臂变号抬高容量四成；AB02 两组都不越界（0.35／0.42）。因此“右膝缺口换模型后依然存在”**撤回为“未决”**：缺口只出现在两个模型都没有数据的角度里。三条轴的读法由此统一为——髋旋转不可解读、腰椎缺口消失、右膝未决，深蹲求解失败**没有任何“人做不到”的容量解释**。见[膝容量有效范围](data/high_flex_knee_range_validity.json)。

## 阶段 1：可信几何

- 卧推／实力举胸肌 atlas 绑定复查加入“锁骨内侧端”几何代理：肩、锁骨、胸廓三点拟合残差降到约 0.1 cm 内，但三条胸大肌路径到各自网格的最远偏差仍约 4.0–16.2 cm，腹部束在前后方向明显分离。几何点残差不能替代逐束解剖配准；先取得胸廓前后方向的可信标志与肌肉起止点对应，再决定是否替换手机当前的路径示意体。[两方案逐点审查](../blender/README.md)。
- 加入胸肋束靠胸骨的第四个几何锚点后，未直接参与拟合的锁骨束和腹部束在合成起点姿态下也接近网格，三束最大表面距离降到约 2.6–3.9 cm。实力举 101 帧只随胸廓／锁骨刚体运动会让最大距离增至 7.7–9.0 cm；路径两端位移驱动的研究形变把它降到 2.6–3.5 cm，全部边长比约 0.70–1.38。已生成并重开的[三束 atlas 实力举研究场景](../assets/blender/opensim_tsm_press_pectoralis_atlas_probe.blend)含 101 帧形态键。四点与动态路径都来自同一合成模型，尚无解剖标志点或真实动作验证；手机已接入候选网格；对应关系与真实动作几何仍待独立验收。[逐帧审查](../blender/README.md)。
- 确定可合法使用的骨骼和肌肉资产；为肌肉建立标准命名、骨骼附着点与包绕路径。
- 对静态解剖网格建立骨段绑定与跨关节变形；逐动作检查关节轴、肌腱路径和穿模。
- 用 Blender/MuSkeMo 输出轻量模型；匹配用户身高、围度和可选肢体长度。
- 验收：输入围度与模型测量一致；动作中肌肉路径与骨骼同步，不穿模或错误翻转。

- 补上了上一条里“不检测穿模或软骨”的验收缺口（`blender/audit_registered_mesh_integrity.py` + `npm run check:registered-mesh-integrity`）：对八肌肉场景的**全部 101 帧 × 8 块网格**逐帧计算边长比、相对该肌肉刚体运动的面法向翻转、以及网格之间与网格—骨骼之间的三角形相交（第一帧已相交的网格对算作参考状态，只报告形变**新增**的穿插），六块骨骼两两之间也做同样测量作为对照。结果：**“不错误翻转”通过**——101 帧内没有任何边越出 0.5–1.5（最小 0.5814、最大 1.4755）、没有面翻转或退化面、自相交不超过站姿参考，比原先只抽查五帧的结论更强；**“不穿模”不通过**——7 对网格在深蹲中段出现新增相交，最深 7.59 mm（胫骨前肌×股骨），另有臀大肌×股直肌 7.50 mm、股直肌×股骨 4.26 mm 等，而**骨网格自己从第 3 帧起就相交**（股骨×胫骨 97/101 帧、最深 6.79 mm；股骨×髌骨 87 帧；股骨×腓骨 71 帧；髌骨×胫骨 73 帧），站姿参考本身也有 22 对网格相交。因此不通过的原因主要是**配准粒度**（静态 Z-Anatomy 骨网格按包围盒中心共同平移，没有软骨间隙；膝附近的肌肉×骨骼相交有一部分是从骨骼继承的），而不是某块网格的形变参数；肌肉×肌肉的三对与骨骼无关，属形变启发式自身。要通过这条验收需要软骨间隙或逐肌肉附着点配准，而不是继续调形变权重。见[逐帧完整性审计](data/registered_mesh_integrity_audit.json)。

- 接着量了“需要多大的关节间隙”（`blender/probe_bone_joint_clearance.py` + `npm run check:bone-joint-clearance`）：不动场景，只假设性地把胫骨侧五块网格沿膝—踝轴远端平移、把髌骨沿“股骨最近表面→髌骨中心”向前平移，2／4／6／8／10 mm 逐级重算相交。**结论是实测的否**——胫骨轴下移 10 mm 后股骨×胫骨仍相交 **81／97 帧**（0 mm 时 97 帧）、股骨×腓骨仍 **20／71 帧**，髌骨向前 10 mm 后股骨×髌骨仍 **69／87 帧**，说明这些网格是配准后互相嵌进去的，不是缝隙太小；能修的只有折起来的接触（股二头肌短头×胫骨前肌 6 mm 归零、股二头肌短头×比目鱼肌与髌骨×胫骨 8 mm 归零），另有四对（股骨×髌骨、臀大肌×股直肌、股直肌×股骨、股中间肌×髋骨）与膝间隙无关——后三对的最深点在离膝关节中心 324–416 mm 的髋部。因此这条验收的出口是**逐骨／逐肌肉配准，而不是开大关节间隙**；手机端研究层说明文字已按这条更正（缓存 v120）。见[关节间隙探针](data/bone_joint_clearance_probe.json)。

- 把“逐骨配准”真的做了一次（`blender/optimise_patella_registration.py` + `npm run check:patella-registration-optimisation`）：既然所有骨骼共用一个站姿平移，就先给**最严重的那一对**——髌骨网格 87 帧插进股骨——搜一个自己的恒定偏移。搜索缓存一次逐帧几何后评价候选常数，代价是股骨与胫骨方向的穿插深度之和加上“离股骨太远”的惩罚（防止把髌骨甩开来假装解决），边界 ±35 mm；67 次评价找到 **28.8 mm** 的偏移（+13.5／−18.0／+18.0 mm），把髌股相交从 **87 帧降到 5 帧（深度 0）**、髌骨×胫骨从 **73 帧降到 0 帧**，代价是**股直肌网格与髌骨在 67 帧里相接**（髌骨本就位于股四头肌腱内，未单独验证）。偏移已真正落地：唯一来源是[搜索报告](data/patella_registration_optimisation.json)，`blender/animate_registered_bones.py`、`blender/probe_attachment_surfaces.py` 与 `src/model.ts` 都读同一个数，整条腿场景链（骨骼＋八肌肉）与四份变体场景已按新配准重建，逐帧审计与关节间隙探针重跑。站姿参考相交对因此从 22 降到 **20**，髌骨五个源路径点到骨面的距离从 4.5–5.3 cm 缩短到 **2.6–3.7 cm**。股骨－胫骨那条没有改善（开间隙 10 mm 仍 81/97 帧），仍需逐骨配准；手机端说明文字与缓存（v121）同步。

- 把“逐骨配准”这条也量到边界（`blender/optimise_knee_registration.py` + `blender/optimise_fibula_registration.py` + `npm run check:knee-registration-optimisation`）：针对剩下的股骨－胫骨 97/101 帧与股骨－腓骨 71/101 帧，把**胫骨（含腓骨）的四种常数方案**各搜一遍——只平移、只换旋转支点、两者叠加、再加站姿倾角；代价是股骨×胫骨／股骨×腓骨／胫骨×跟骨三个方向的穿插深度之和，加上“膝面座位与踝面座位相对基线不得漂移”的惩罚（权重 5.0、±60 mm／0.2 rad、各 200 个最近顶点算座位），因此不能靠把胫骨推进跟骨或拉开关节假装解决。四个方案都没顶到边界：只平移 **97→81 帧**（腓骨 71→**0**、深度 12.59→8.17 mm，但膝面座位 6.35→11.59 mm）、只换支点 **97 帧不变**（腓骨 71→28）、支点＋平移 **85 帧**、再加倾角 **83 帧却新增 20 帧胫骨×跟骨相交**。结论是**实测的否**：没有任何常数能修掉股骨－胫骨，因为每帧骨骼运动是复合螺旋运动，其轴离站立膝面中心 **364.85 mm** 且沿轴平移为零、各帧同轴，一个常数支点无法跟随屈曲角。**最诱人的“只平移”没有被采纳**——它把 8 个胫骨源点到骨面的距离全部推远（胫骨前肌 P3 0.38→1.79 cm、比目鱼肌 P1 0.18→1.28 cm），而配准体系的独立旁证正是这组距离；附着面筛查现在会并列算出被否决偏移下的距离作为依据。只动腓骨单独搜也只能 71→52 帧。因此膝关节这条验收的出口是**关节软骨／接触建模，或明确写出这一条不通过**；手机端说明文字与缓存（v122）同步。见[膝关节搜索报告](data/knee_registration_optimisation.json)、[腓骨搜索报告](data/fibula_registration_optimisation.json)。

## 阶段 2：三个动作的动力学

- 深蹲示意现可选杠铃前后位置 −6／0／+6 cm，手机三维杠铃、Blender 5.1.2 动作场景和静态重力力臂计算共用同一位置函数；手臂随杠铃握持点移动，躯干与下肢仍用同一示意姿态。Blender 保存后 9 帧杠铃位置核对通过，v38 离线缓存检查和 Android 资源同步通过。此功能展示负重作用线假设的影响，不自动求出完整关节净力矩。更贴近杠铃深蹲的 Pürzel 等 2026 年低杠位研究仅公开组层结果，逐人原始数据因敏感性未开放，目前不能完成个体误差验收。
- 修正前的深蹲示意在默认最深帧把 72 kg 身体与 20 kg 杠铃合重力线放在踝后约 16.8 cm；修正躯干长度、髋部位移和杠铃握持后，新姿态约为踝后 2.0 cm。已从 12 个公开缩放 OpenSim 模型提取同一套体段质量比例，做 135 组静态平衡情景探针。数值只能检查示意姿态的静态几何合理性，不是实测足底压力。手机端的 390 px 深蹲负重视图已检查，结果及质量模板见 [OpenSim 研究记录](OpenSim研究记录.md)。
- 已用两名公开受试者的实验逆运动学、个体缩放模型和独立力板复核动态整体力平衡：自重深蹲中 (m(g+a_{COM,y})) 的垂直力误差约 29／20 N，只有 (mg) 时为 284／155 N；105–305 ms 数值平滑窗口的结论一致。现把预设轨迹的同一公式以**示意情景**接入手机，并让用户选择动作周期；这只是模型输出，没有使用者的实测运动。见[动态数据核查](动态深蹲验证数据.md)和[人工轨迹探针](data/squat_dynamic_grf_probe.json)。

- 深蹲预研已完成：按原型姿态从 OpenSim 官方简化模型导出同源的单侧关节位置、九肌肉路径点、路径长度与力臂，已在手机视图中对齐显示。修正后的姿态再次运行自重、20 kg、60 kg 及杠铃位置 ±6 cm 的 MocoInverse；结果对作用线和肌肉被动力敏感，关闭被动力时臀大肌激活达到上限。历史轨迹结果与当前轨迹分开记录，见 [OpenSim 研究记录](OpenSim研究记录.md)。这些力结果未进入手机发力视图。
- 审查了 MIT 许可的全身杠铃动作 XML 生成器 [OpenSim_Models](https://github.com/D-sorganization/OpenSim_Models)：本机 OpenSim 4.6 对其原始深蹲、卧推和挺举 XML 实际读入 0 个体段与 0 kg；尝试补足集合结构后均因腕关节轴共线失败，模型也没有肌肉元素。审查脚本和[结果](data/third_party_exercise_model_audit.json)已保存，不把该候选作为已验证的发力模型。
- 已进一步用 175/190 cm、72/90 kg 四组输入缩放单腿模型的几何与总质量，在相同近似 60 kg 负重下运行 MocoInverse。计算对体重输入产生响应，但不是经验证的个体预测；数据与限制仍保留在 [OpenSim 研究记录](OpenSim研究记录.md)。
- 已对一个公开的 5/15 kg 蹲式搬箱 IK/ID 示例做描述性负重趋势筛查，重载试次的 L5/S1 力矩列更高；动作、外力位置和模型不同，不能用作当前杠铃深蹲的验证。
- 从 Georgia Tech 官方 Second Skin 数据集按字节范围提取 AB01、AB02 各一组无负重与 25 lb 背心静态半蹲，获得同步关节角度和 OpenSim 力矩。四个试次均有约 4000 个 5–25 秒有效样本，但两人的组间髋、膝、踝角度范围都不重叠，且膝力矩负重差异方向相反；这些中位数**不能**直接验证负重因果趋势。见[数据核查](SecondSkin深蹲验证数据.md)。
- 已从 Scherpereel 等的 Georgia Tech 动态深蹲数据中，提取 12 人的自重与额外 25 lb 试次，用左右髋膝踝角度和动作阶段配对。11 人达到预定覆盖门槛；负重试次的垂直地面反力与髋伸展方向力矩变化一致，膝力矩方向不稳定。已从 AB01、AB02 的原始标记、力板与缩放模型复算四段 IK/ID；六个下肢角平均差均小于 0.01°，12 个关节／片段对照中 11 个更接近 CSV × 体重，支持按 N·m/kg 解读。已完成独立受试者留出预测基准，但其误差尚不支持个人发力指导；见[动态数据核查](动态深蹲验证数据.md)及[逐人结果](data/dynamic_squat_angle_match.json)。

- **检查的第五条写法纪律**（增补之二十六）：源码级的文案断言也要限定在“该说话的那张卡片”里。用 `main.includes(短语)` 搜整份 `src/main.ts`（约 1050 行、四个视图描述加全部界面代码）时，一句话只要挪到别的卡片或注释里，断言照样通过，而它点名的卡片其实已经不说了；四条研究层检查的 16 条短语现在限定在该视图标题与下一个标题之间的描述区间（共享 `scripts/card-text.mjs`），失败信息会指出“这条仍出现在别处，所以整文件搜索会照常通过”。
- **检查的第四条写法纪律**（增补之二十三、二十四）：只验“拒绝”的边界检查会有一个空过口子——如果解码器把所有输入都拒了，全部 `assert.throws` 仍然成立；所以边界要**两侧都验**（上限 N 条成功、N+1 条被拒；每个字段在登记表的最小值与最大值处被接受、越界一格被拒），必填缺失要断言是“拒绝”而不是“静默补默认值”，并且守卫（例如 1 MB 文件上限）要与“拒绝时没有副作用”一起断言。**正交不等于没有镜像**：一组被镜像的基仍然正交归一，只有行列式能发现它，而基于长度的断言对旋转完全不变——所以凡是有旋转矩阵的数据都要另行断言行列式 = +1（并注意共用助手已经做过的事，别让某一条检查成为漏掉的那个）。参考数据的**键集合要逐帧核对**，不要只从第 0 帧读一次：否则少一条、多一条会在后面以 TypeError 崩掉，报错指向读取处而不是哪一帧。**样本集合本身也要验**：按坐标挑样本的断言（例如“端点没有移动”按 `|y| = 0.2` 挑顶点）在换了几何体后可能一个样本都挑不到而照样通过，所以要把样本数数出来并要求大于 0；一份“5 个样本”如果是同一个点的 5 份拷贝，所有逐点断言都会通过而对照只剩一个点，所以要另行要求下标互不相同——同时记住，样本数达标不等于样本有代表性（5 个点验几千个顶点的网格仍然很薄）。
- **界面检查的三条写法纪律**（增补之二十、二十一、二十二）：断言必须限定在“该说话的那个容器”上，不用整页文字搜索（`器械` 在构建产物里出现 5 次，抹掉表单标签后整页搜索照样通过）；不能只在容器里已经出现数字时才要求限定，要写明每个输出在哪些界面状态下**必须可见并显示内容**，否则容器被清空或不再渲染也会悄悄通过；判断布局不能用文档级 `scrollWidth` 一条——面板是 `overflow: hidden`，比视口宽的内容会被裁掉反而不产生滚动（实测注入 600 px 子元素后文档 `scrollWidth` 仍是 390），要逐个元素比较边缘并豁免确实可滚动的条带。用户数据的断言要覆盖全部字段，不用抽样；"清空"要核对回到现场读取的默认值。
- **改源码的写法纪律**（增补之二十九）：不要用 PowerShell 的 `Get-Content`／`Set-Content` 重写仓库源码——PS 5.1 的 `Set-Content -Encoding UTF8` 会写入 BOM 并把行尾从 LF 变成 CRLF（本仓库其余文件是 UTF-8 无 BOM、纯 LF），`>` 重定向还会把输出写成 UTF-16LE，两者都会制造整文件级的假差异。改源码用编辑工具或按字节读写的脚本；改完把源文件的行尾数一遍（`crlf` 必须为 0），并确认构建产物大小没有意外变化。
- **键盘与语义可达性**（增补之二十八、二十九）：动作／视图切换按钮用 `aria-pressed` 暴露状态（与高亮类同步），三维容器可聚焦、可用方向键旋转俯仰、也可用 `=`／`+`／PageUp 与 `-`／PageDown 缩放（`role="group"`＋`tabindex="0"`＋名称写明按键，缩放边界与滚轮一致），`npm run check:ui-dom` 增到 13 条行为：其中一条真的按方向键再读回相机朝向、并用字母键确认相机不动，另一条按缩放键、试到两端边界、确认相机没有被转。边界：没有屏幕阅读器实测、也没有 200% 缩放或全流程键盘走查；触摸手势（双指缩放）本来就没有，本轮也没有加。其中“对比度”这半已在增补之三十六补上并写成 `npm run check:contrast`，**色盲可分辨性**仍未做。
