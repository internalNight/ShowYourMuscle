# 网页版精细肌肉与动作

## 当前可以试什么

`npm install && npm run build && npm run preview`，打开 `http://127.0.0.1:4173/`。默认同时显示精细肌肉表面与透视骨骼；可旋转、缩放、播放或拖动进度条，切换静止、徒手深蹲、卧推、实力举。骨骼、肌肉表面及肌肉肌腱路径可分别开关。主要肌群卡列出当前动作中路径变长、变短幅度最大的肌束，点选可定位到对应网格和 OpenSim 路径；默认仅突出这些肌束，可关闭该开关查看全部颜色。前半程与动作起点比，回程与折返点比，因此回程方向会反转；自定义姿态与站立静止比，并分开显示左右侧。红色代表整条肌肉肌腱路径变长，蓝色代表变短。读数同时保留站立参考长度。颜色和排名不是激活、力量或发力点。

如需自定义姿态，用已安装 OpenSim 4.6 与 SciPy 的 Python 运行 `.cache/opensim-venv/Scripts/python.exe scripts/live_pose_server.py --port 5173`，打开 `http://127.0.0.1:5173/`。七组关节滑块控制左右对称姿态；也可单独拖动任一手或脚的圆点，松开后由同一 OpenSim 模型逆运动学拟合该侧肢体，并重新计算全部体段和肌肉肌腱路径。拖动一侧不强制另一侧跟随；超出模型可达范围会显示目标误差。拖拽求解约需数秒，不是连续动力学仿真。只启动 Vite 静态预览时，预设动作仍可用，自定义姿态服务不可用。

静止和所有动作均使用 `cyclistFullBodyMuscle.osim` 的 80 个体段变换、520 条肌肉肌腱路径及长度。网页不切换另一套动作模型。Z-Anatomy 提供 68 块肌肉与 91 块骨表面，配准并绑定到同一套 OpenSim 骨段；它们只是显示几何，不提供第二套关节运动学或肌肉力学。网页加载约 10.5 MB 肌肉 GLB、6.4 MB 骨 GLB、0.39 MB 蒙皮权重及约 19.9 MB OpenSim 动作数据；手机浏览器的性能尚需实机验收。

## 来源、许可和几何精度

- [OpenSim 主模型](https://github.com/ross-wilkinson/opensim-model-fullBodyMuscleActuated)，固定提交 `3cfbe329a8ef9412494980419cb7177c41183a53`，MIT。`assets/opensim/cyclistFullBodyMuscle.osim` 是用于本地实时服务的同源副本。模型面向骑行，作者指出椎骨显示不准确，上身驱动有局限。
- [Pose2Sim 几何库](https://github.com/perfanalytics/pose2sim/tree/68304b47195dac80bc341cdfd9669140609358c4/Pose2Sim/OpenSim_Setup/Geometry)，BSD-3-Clause。只补主模型已引用的同名网格。83 个引用网格进入画面；37 个引用缺文件，12 节胸椎因源模型显示错位排除。许可见 `public/models/NOTICE-unified-opensim.txt`。
- [Z-Anatomy](https://github.com/Z-Anatomy/Models-of-human-anatomy) 解剖表面，CC BY-SA 4.0，包含 BodyParts3D 衍生内容。配准后的肌肉与骨表面及权重作为衍生内容继续按 CC BY-SA 4.0 分发，署名见 `public/models/NOTICE-z-anatomy.txt`。这套表面没有原生 OpenSim 肌肉纤维模型。

`scripts/build_unified_muscle_surfaces.py` 以 15 对同名骨的中点拟合全局相似变换，并为上臂和前臂表面做局部骨位移修正。配准报告写入 `public/data/unified_muscle_skin.json`：骨中点 RMS 约 3.6 cm；髋和股骨约 1 cm，胫骨约 2.3 cm，未做局部修正前前臂约 5–6 cm。`scripts/build_unified_anatomy_bones.py` 将骨表面按相同配准绑定到 OpenSim 体段。肌肉用起点、主骨段、止点三段权重，肌腹中段主要跟随主骨，近附着点再向相邻骨段过渡，避免双骨线性绑定把整块肌腹拉塌。缩短时最多约 13% 的径向鼓起是**外观近似**，并非肌纤维或体积的实测模拟。穿模、附着点和个体比例有待解剖专家逐块核验。

## 动作轨迹与边界

`scripts/export_unified_opensim.py` 输出 101 帧/动作，动作角度是明确写出的教学预设，**不是**从实测训练录像做的逆运动学。徒手深蹲在脚跟固定的前提下提高髋、膝屈曲深度，并检查脚尖离地误差；卧推将躯干放在凳上，调整下肢关节使双脚接近全足着地，再用手部关键姿态减少握距变化；实力举采用该模型实际可达的杠铃绕头轨迹及肩轴向旋转，使上举过程中双手尽量保持在同一握距。网页中的杠铃和凳仍只是视觉参照，**手握接触、重心平衡、外力和肌肉激活没有求解**。

动作约束参考：[OpenSim 官方深蹲起立示例](https://opensimconfluence.atlassian.net/wiki/spaces/OpenSim/pages/53089435/Moco%3A%2BPredict%2Ba%2BSquat-to-stand)说明了固定脚与肌肉驱动求解的标准流程，但其示例只有平面 3 自由度、9 条肌肉，不能直接替代此全身模型；[17 名运动员深蹲角运动学研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC11565377/)报告髋、膝、踝与杠铃轨迹；[卧推技术与 OpenSim 肩部载荷研究](https://www.frontiersin.org/journals/physiology/articles/10.3389/fphys.2024.1393235/full)使用实测杠铃、肩肘标记与受试者模型；[卧推和过顶推举的关节链研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC12372072/)强调杠铃对两手的共同运动约束。当前预设借鉴这些约束，并没有导入研究者的原始动作捕捉数据，因此仍需教练及运动生物力学人员评审。

原骑行模型的肩升举角上限约 2.01 rad，不足以达到过顶锁定。导出和实时服务都把同一 OpenSim 模型的肩关节数值范围临时延长至 3.1 rad；该范围的肌肉包绕与长度变化未经验证，尤其不能据此推断肩部力量。卧推的凳和杠铃仅是视觉参照，没有力学接触或重量。模型的姿态、体型和肌肉量尚未按个人参数调整。拖动手脚后只做位置拟合；没有重新求解肌肉激活、动态力或关节反力。

当前卧推预设中，`PECM1` 从最低点到最高点的模型整条肌肉肌腱长度变化很小；这反映该骑行来源模型与当前关节轨迹的组合，**不能据此判断胸大肌不发力**。本阶段只做几何长度教学，不将路径长度当作肌纤维长度，也不使用实测数据拟合或推断肌肉力量。

## 复现和检查

在 `.cache/model-candidates/opensim-model-fullBodyMuscleActuated` 克隆主模型，在 `.cache/model-candidates/pose2sim` 克隆 Pose2Sim；安装 OpenSim 4.6 Python、NumPy、Trimesh 和 SciPy。执行：

```powershell
python scripts/export_unified_opensim_meshes.py
.cache/opensim-venv/Scripts/python.exe scripts/export_unified_opensim.py --samples 101
python scripts/build_unified_muscle_surfaces.py
python scripts/build_unified_anatomy_bones.py
npm run check:unified-data
npm run build
npm run check:unified-ui
.cache/opensim-venv/Scripts/python.exe scripts/live_pose_server.py --port 5173
```

发行的预计算数据已在仓库中；普通网页版运行不需要安装 OpenSim。当前验收包括 304 帧、520 条路径、68 块肌肉表面、91 块骨表面、脚部接触近似、卧推/实力举手部位移，以及浏览器加载、动作切换、手脚拖动和读取数值。旧版 v133 研究脚本与结果仍在仓库中，不代表当前首页。

## 接下来

1. 逐块检查 OpenSim 路径与 Z-Anatomy 肌肉、骨表面的附着关系，重点优化肩、肘、膝附近的穿模与厘米级配准误差；缩短时鼓起仍只作为几何外观。
2. 继续用关节范围、手脚与器械轨迹等几何条件审查三项预设动作，尤其检查过顶肩部包绕路径、杠铃握距和脚部接触。不需要实测数据拟合。
3. 扩展可拖动的关节并提高逆运动学速度，让使用者直接探索某个姿态对主要肌群路径长度的影响。
4. 网页版几何展示稳定后，控制手机内存、加载和离线体积。若未来另做受力分析，需要独立模型和验证，不纳入当前几何版本。
