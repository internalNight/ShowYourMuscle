# 上肢力矩与肌电独立筛查

## 为什么做这项核查

手机原型有卧推和实力举的预设姿态、肌肉肌腱路径长度与杠铃重力外力矩，但还没有经过验证的个人肩肘净力矩或单肌肉力。为检查“少量身体参数能否支撑逐帧发力图”的前提，选用 [Quesada 等人的开放上肢数据集](https://zenodo.org/records/11209324)。它记录了 17 人的肩肘多关节跟踪任务，提供身高、体重、臂段长度、同步关节角与角速度、12 路经 MVC 归一化的表面肌电，以及研究处理后的肩肘关节力矩。资料按 CC BY-SA 4.0 发布。

这项任务**不是卧推或实力举**，也没有逐块肌肉的实测力量。它只用于检验模型输入和跨人的泛化风险；结果不进入手机个人发力高亮。

## 可复算方法

`scripts/inspect_upper_limb_torque_zip.py` 以 HTTP Range 读取原始 1.4 GB ZIP 的目录，并且只取每人 `MJ/T0` 的四个已处理 CSV 与个人元数据，约 66 MB 网络传输。压缩成员的 CRC 由 Python ZIP 读取器检查；未下载整个 ZIP，因此记录中的 MD5 只作**发布者提供的标识**，不是本地整包哈希复核。原始子集只存于被忽略的 `.cache/upper-limb-torque/`，不进入手机包。

`scripts/benchmark_upper_limb_torque.py` 检查四条时间轴均为 100 Hz 且逐点对齐，再每五帧取一帧，共 17 人、10,000 个时间点。每次留出**整名受试者**，用另外 16 人拟合固定正则强度 10 的线性岭回归，并仅用训练人的统计量标准化。对照输入分别为训练人均值、身体尺寸、身体尺寸加肩肘角度／角速度、以及再加 12 路肌电。误差先逐人计算，再取 17 人中位数；配对改善的区间按人重采样。详细数字和每人结果保存在[机器可读审查表](data/upper_limb_torque_holdout_probe.json)。

```powershell
python scripts/inspect_upper_limb_torque_zip.py --extract-trial MJ/T0 --all-subjects
python scripts/benchmark_upper_limb_torque.py
python scripts/inspect_upper_limb_torque_zip.py --extract-models --all-subjects
python scripts/audit_upper_limb_model_parameters.py
& '.cache/opensim-venv/Scripts/python.exe' scripts/probe_upper_limb_model_paths.py
& '.cache/opensim-venv/Scripts/python.exe' scripts/audit_upper_limb_torque_feasibility.py
& '.cache/opensim-venv/Scripts/python.exe' scripts/benchmark_upper_limb_force_prior.py
```

| 输入 | 肩关节力矩逐人 MAE 中位 | 肘关节力矩逐人 MAE 中位 |
| --- | ---: | ---: |
| 其他人的平均力矩 | 6.417 N·m | 3.375 N·m |
| 身高、体重、上臂与前臂长度 | 6.272 N·m | 3.449 N·m |
| 再加实测肩肘角度与角速度 | 3.601 N·m | 2.448 N·m |
| 再加 12 路实测肌电 | 3.577 N·m | 2.261 N·m |

肌电相对姿态输入的逐人配对误差改善中位，肩部为 **0.116 N·m**、肘部为 **0.336 N·m**；按人重采样的 95% 区间分别为 **−0.233 至 0.309** 与 **−0.236 至 0.699 N·m**。肩部 10／17 人、肘部 12／17 人改善，不能称为稳定的跨人收益。S14 的前束三角肌已处理肌电第 99 百分位为 MVC 参考值的 **3.694 倍**，肩部加入肌电后的 MAE 从 **3.926** 增至 **11.736 N·m**。超过 MVC 参考值不必然是错误，可能与 MVC 测试、任务状态或信号质量有关；主分析保留该人，没有事后剔除。

### 个体模型的肌力参数

同一数据包的 17 份 `scaledModel.osim` 每份都有 12 块肌肉。逐个解析 `max_isometric_force`、`optimal_fiber_length`、`tendon_slack_length` 后，发现 **12／12 块肌肉的最大等长力在 17 人间完全相同**，而 12／12 块肌肉的最佳纤维长度和肌腱松弛长度都随缩放改变。例如胸大肌 `PECT` 的最大等长力在所有模型中均为 **444.3 N**，最佳纤维长度范围为 **0.1349–0.1875 m**。[逐肌肉参数审查](data/upper_limb_model_parameter_audit.json)保留全部数值。这个检查只说明文件中的参数设定，不能推断参与者的真实肌力；也不能把几何缩放误称为已经完成个人强度标定。

`scripts/probe_upper_limb_model_paths.py` 还用本机 OpenSim 4.6 重新载入 S01 的 11 骨段、11 关节、12 肌肉模型，把 `MJ/T0` 的五帧关节角写入模型后计算肌肉路径长度和肩／肘力臂。七个输入坐标的最大重现误差低于 **1×10⁻⁹ rad**；胸大肌路径在这五帧约为 **0.138–0.146 m**。[路径和力臂逐帧数据](data/upper_limb_opensim_path_probe.json)可用于后续建立同一模型的力矩平衡审查。原包缺少模型引用的 VTP 显示网格，OpenSim 提示缺失，但路径计算成功。该探针只有一人的五帧，没有重放外力、求解肌肉力或验证卧推。

### 两关节力矩的容量与非唯一性

`scripts/audit_upper_limb_torque_feasibility.py` 将每个人模型计算的肩／肘力臂组成 2×12 矩阵，仅假定每块肌肉的张力在 **0 到该模型的名义最大等长力**之间，用线性规划检查能否重现数据包的两项关节力矩。每人约每 0.5 秒取一帧，并加上五个详细帧。17 人的 **1,071／1,071 帧**在这些宽松约束下均可行，输入姿态经模型约束组装后的最大坐标偏差为 **0.003324 rad**（约 0.19°）。这表示当前矩阵和宽松参数没有出现明显的两关节容量矛盾，**不表示已经求出了真实肌肉力量**；求解尚未处理纤维力长速关系、被动力、其它关节、外部接触或原研究的逆动力学约定。[逐人和逐帧结果](data/upper_limb_torque_capacity_screen.json)。

对每人五帧，再分别最小化、最大化某一块肌肉的力，同时保持**相同的两项关节力矩**：

| 肌肉 | 85 个可行详细帧中，力值区间跨越至少 95% 名义上限的帧数 |
| --- | ---: |
| 胸大肌 `PECT` | 85／85 |
| 前束三角肌 `DELTAnt` | 73／85 |
| 肱三头肌长头 `TRILong` | 85／85 |

例如 S01 第一帧的胸大肌在这套约束下可以是 **0–444.3 N**，肱三头肌长头可以是 **0–771.8 N**，两端解仍重现相同肩肘力矩。这些宽区间反映模型和约束的**不可辨识性**，不是人体真实肌肉力可能任意切换的结论。后续必须加入经过校准的肌肉生理、动作外力、可能的共收缩约束，并用独立肌电等资料核查；只把关节力矩配平，不能生成可信的单肌肉红色高亮。

### 一个具体分配先验的肌电趋势核查

`scripts/benchmark_upper_limb_force_prior.py` 在上述可行域中选择使 `Σ(Fᵢ/Fmaxᵢ)²` 最小的解。它**使用实验给出的肩、肘力矩和姿态作为输入**，不是手机可以只凭体型和训练记录做出的前向预测。17 人每约 0.5 秒一帧，共 1,020 帧的两关节力矩残差最大约 **3.2×10⁻¹⁴ N·m**；随后将求出的归一化肌肉力趋势与同一时点的 MVC 归一化肌电做逐人 Spearman 相关，再跨人取中位数。肌电不参与求解，也没有逐人调整延迟或参数。[完整逐人结果](data/upper_limb_force_prior_emg_screen.json)。

| 肌肉 | 求解值／肌电逐人相关中位 | 17 人重采样 95% 区间 | 模型路径长度／肌电逐人相关中位 |
| --- | ---: | ---: | ---: |
| 前束三角肌 `DELTAnt` | 0.843 | 0.806–0.883 | −0.497 |
| 胸大肌 `PECT` | −0.152 | −0.255 至 −0.094 | 0.103 |
| 肱三头肌长头 `TRILong` | 0.108 | 0.049–0.215 | 0.123 |
| 肱二头肌长头 `BICLong` | 0.705 | 0.644–0.763 | −0.135 |

这项任务的前束三角肌、肱二头肌趋势与肌电较一致，但胸大肌预测方向相反，肱三头肌长头的一致性很弱。**零残差地配平关节力矩并未通过所有肌肉的外部趋势核查。**肌电不是肌肉力真值，长度与肌电的相关性也不等于发力因果；这张表只说明在该任务、该先验与零延迟比较下，不能把求解值直接用于产品高亮。还需目标杠铃动作、外力与个人参数的独立验证。

## 对产品的约束

- 仅凭身体尺寸给出的预测在这项任务中无法描述同一次动作内随时间变化的力矩；训练重量和次数也不能直接补出肩肘轨迹或肌肉分担。
- 实测姿态可改善这项**研究任务**的关节层误差，但手机当前只播放预设姿态，没有测量使用者动作。研究关节力矩也不等于单肌肉力量。
- 即使额外取得 MVC 归一化肌电，简单跨人模型仍有明显个体差异；因此未来若做红色发力图，需要匹配杠铃动作的逐帧运动学、手部外力与凳面／足底支撑，并对单肌肉预测做独立验收。

该筛查不能证明所有少参数模型都不可行，也不能把这组非杠铃试验的误差当作卧推或实力举产品误差。下一步优先寻找或采集**与目标动作一致**的杠铃、关节、支撑与肌电同步数据；无需让手机用户上传任意视频。
