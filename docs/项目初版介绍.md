# 肌动图谱：项目初版介绍

更新：2026-09-25。名称为暂名。

## 一句话介绍

用户在手机上输入少量身体参数和已有训练记录，生成接近自身体型的三维肌骨模型；选择卧推、深蹲或实力举等预设动作，逐帧查看肌肉长度变化、关节受力与经过模型估算的肌肉需求，辅助理解动作。

## 目标用户与场景

- 健身者：训练前快速查询动作过程、参与肌群和姿势改变的影响。
- 教练和运动教师：用可旋转、可逐帧查看的模型讲解动作。
- 康复与特殊动作教学人员：在明确适用范围和验证程度的前提下，用模型辅助解释运动机制。

产品应能在手机上迅速启动，核心内容可离线查看。输入应以数字和少量选择项为主，不要求拍摄视频或进行新的测试。

## 产品价值

现有产品和论文分别展示了三维肌肉动作、肌肉活动高亮、肌骨动力学计算、个体模型缩放与手机动作采集。2026 年的 [MyoMechanix](https://arxiv.org/abs/2608.26094) 进一步覆盖了负重动作、同步三维姿态与肌电教学研究。本项目要把这些能力整理成面向健身现场的连续流程：**少量参数标定 → 可操控模型 → 预设动作 → 长度变化与估算发力分视图 → 简洁解释**。

这里的差异化目标是产品设计方向，并不主张“肌肉标红”或“手机三维解剖”本身是首次出现的发明。

## 功能需求

### 1. 个性化模型

用户输入身高、体重，并可补充体脂率、放松臂围、胸围、腰围、大腿围、小腿围；臂展和内侧腿长作为可选的骨骼比例修正。模型需要同时更新可见轮廓、骨骼段、肌肉附着路径及体段质量。围度不直接等于某一块肌肉的体积。

### 2. 训练记录标定

可录入已有的卧推、深蹲、实力举等训练记录：动作/变式、重量、次数、是否接近力竭。记录首先用于估算**动作能力范围**，进而约束相关肌群的整体力量参数。单次复合动作成绩不足以唯一确定单块肌肉的质量或最大力量。用户无需进行额外测试。

### 3. 动作探索

首批动作：杠铃深蹲、平板杠铃卧推、站姿实力举。可播放、暂停、逐帧拖动、旋转和缩放人体，并切换骨骼、肌肉及半透明外表层。每个动作须保存器械质量、动作路径、关节角度和动作阶段。

### 4. 分开显示三个量

- **长度变化**：肌肉路径相对该动作起点的变化，以及变长/变短趋势。
- **估算活动度**：模型求解的肌肉激活水平，只有完成计算与校验后才能显示数值。
- **估算力量**：模型求解的肌肉或关节负荷，标明单位、假设和适用范围。

主动发力的肌肉也可能在变长，尤其在离心阶段。颜色、图例和说明必须保留这种区别。不得仅依据“变短”将肌肉标记为“发力”。

### 5. 解释与可信度

每个输出说明它是用户输入、几何计算、模拟估算还是教学示意。对个体化肌肉体积和力量使用范围或等级，不展示没有依据的精确数字。健身指导应解释模型假设与动作差异，不宣称诊断或实测结果。

## 输入端与输出端

| 输入 | 用途 | 输出 |
| --- | --- | --- |
| 身高、体重 | 整体尺度及质量约束 | 个人化三维体型与骨骼比例初值 |
| 体脂率、局部围度 | 外轮廓与软组织分布约束 | 匹配围度的外形、内部结构估计范围 |
| 臂展、内侧腿长（可选） | 肢体长度修正 | 更贴近个人的关节位置 |
| 训练记录与接近力竭程度 | 动作能力标定 | 与动作相关的力量能力范围 |
| 动作、负重、变式、时间轴 | 动作与外力条件 | 关节姿态、肌肉长度；后续接入关节力矩与肌肉需求估算 |

数据细节见[输入输出与数据约定](输入输出与数据约定.md)。

## 技术路线

1. **Blender**：制作正式的骨骼、肌肉表面、附着点和动作资源。用 MuSkeMo 等工具管理肌骨路径，输出模型与动画。
2. **肌骨计算**：用 OpenSim/Moco 或经验证的等效模型，结合动作轨迹、外负重、体段参数计算肌肉长度、力臂、关节力矩和肌肉需求。预设动作可预先离线计算；个性化参数超出已计算范围时，应回到计算服务或明确降低输出精度。
3. **手机运行**：发布轻量化三维资源和分帧计算结果，手机端负责渲染、交互、插值与解释。先用可安装的移动网页原型验证交互，再决定原生封装。
4. **验证**：几何层核对测量输入与生成体型；动力学层核对已发表研究、动作数据和条件变化趋势；教学层验证使用者是否能正确区分拉伸与发力。

## 最终实现形式

目标是可在 iOS 与 Android 上使用的手机 App，打开后可离线查阅核心预设动作和个人模型。应用数据优先保存在设备本地；是否提供账号同步由后续产品需求决定。桌面 Blender 是内容制作端，不作为最终用户入口。

## 当前开发边界

仓库第一阶段先验证数据契约、参数输入、三维呈现、动作控制及长度变化的分离显示。当前程序生成的几何是**教学占位体**：身高、部分围度和可选肢体长度影响三维示意，体重与体脂率形成粗略外形先验，训练记录保存并显示动作级能力估计。Blender 动作场景与手机端共用三种动作姿态。深蹲另用输入体重、公开模型体段质量比例和杠铃位置估算静态重力作用线；这还没有实测足底压力和动作加速度。OpenSim 参考页已接入深蹲九条右腿肌肉路径，以及包含胸大肌、三角肌、前锯肌和斜方肌的单侧胸廓—肩胛模型 33 束路径与力臂；实力举的上举轨迹是人工角度扫掠；卧推另有基于该模型仰卧人工手部轨迹拟合的 101 帧、33 束路径研究，手部目标偏差最大约 1.0 cm。两者都不是实测训练动作。Arm26 六肌肉数据保留作旧版对照。三组参考几何可按身高统一缩放，但没有按体重、围度和训练记录做个体动力学标定。研究脚本也已用修正后的深蹲姿态运行 0／20／60 kg 肌肉驱动求解及杠铃位置敏感性对照，但[质量检查](OpenSim研究记录.md)显示该简化模型尚不足以给用户做发力指导。已生成并同步 Capacitor Android 工程；用户确认 Google SDK 许可后安装所需平台组件及 JDK 21，调试 APK 已编译成功并核对包内核心资产，尚无连接设备可做真机测试。尚未建立可声称解剖准确的完整人体，当前界面不显示“实际发力值”。
