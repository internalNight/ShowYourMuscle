# 输入、输出与数据约定

**数据存放与出网**：所有输入都只保存在本机 `localStorage`，只有用户主动「导出备份」时才会写出 JSON；应用没有账号、云同步、统计或广告，包里唯一的网络请求是读取安装包自带的深蹲参考数据。权限、清单、签名与调用面的逐项审计见[隐私与本地数据](隐私与本地数据.md)与[包内审计](data/shipped_package_audit.json)。**导入／导出格式**为 `{ format: 'muscle-atlas-local-backup', version: 1, exportedAt, profile, training }`——只有这五个键，其余设置不进入备份；该往返由 `npm run check:ui-data-flows` 在真实浏览器里每次重跑。

**每个输出的来源与置信**：界面里显示数字的容器带 `data-status`／`data-source`，类别与必须出现的限定登记在[输出与置信登记](data/output_provenance.json)；`illustrative` 是几何示意、`scenario` 是用户输入代入固定力学假定的情景、`estimate` 是训练记录的经验公式粗估、`research_reference` 是公开实验或 OpenSim 研究的群体结果，而 `measured`（对用户本人的实测）刻意保持未使用——应用里没有任何数值来自对这名用户动作、关节力矩或肌肉发力的测量。`npm run check-output-provenance` 会核对登记表、源码属性与真实浏览器里渲染出来的文字。

**同一份登记表还规定“该显示的时候必须真的显示”**：`states` 列出五个界面状态（默认深蹲受力视图、录入记录后、12 人自重深蹲研究参考、卧推、实力举），每个输出的 `shows` 声明自己在哪些状态下必须可见并显示内容——`digits` 表示可见、非空且含数字（因此必须带限定），`text` 表示可见、非空但没有数字（例如尚无记录时的引导语）；没有列出的状态要求它此时不可见或为空。这样一来，“限定句一直都在”不能靠“容器一直是空的”来满足：把某个该显示数字的容器清空或让它不再渲染，检查就会失败。

## 输入字段

| 字段 | 单位 | 约束 | 用途 |
| --- | --- | --- | --- |
| `heightCm` | cm | 必填，合理成人范围校验 | 身体整体尺度 |
| `weightKg` | kg | 必填，合理范围校验 | 总质量约束；当前示意外形的全局先验及深蹲静态重力作用线情景 |
| `bodyFatPct` | % | 可选 | 全身软组织先验，不确定局部分布；当前示意脂肪与瘦体重尺度 |
| `upperArmCm` | cm | 可选，放松状态、上臂中点 | 上臂外轮廓与示意上臂肌腹粗细 |
| `waistCm` | cm | 可选，固定测量位置 | 腰腹外轮廓与示意腰腹、背部肌腹粗细 |
| `thighCm` | cm | 可选，大腿固定测量位置 | 大腿外轮廓与示意大腿肌腹粗细；研究层三块大腿网格横向尺度 |
| `calfCm` | cm | 可选，小腿固定测量位置 | 小腿外轮廓与示意小腿肌腹粗细；研究层胫骨前肌和比目鱼肌两块网格横向尺度 |
| `armSpanCm` | cm | 可选 | 上肢长度修正 |
| `inseamCm` | cm | 可选 | 下肢长度修正 |

测量位置已在「身体参数」卡片内的**测量位置图示**中用正视图标出，并与表单并列列出每个字段的必填／可选状态和量尺说明。图示、图例与表单共用 `src/domain.ts` 中的同一份字段清单，`npm run check:measurement-sites` 核对三者一一对应，避免文字标签与图示漂移。该图只说明量尺放在哪里；所有数值仍由用户自报，App 不测量用户身体。用户体脂率可能来自不同设备或公式，在表单与图示中均标记为自报估计值。

四项围度只控制几何外形。`scripts/check-body-measurements.mjs` 核查各项增大时对应的示意肌腹变粗、其他部位不受该项直接改变，并核查手机与 Blender 导出的粗细规则一致。围度不能分解为肌肉、脂肪和骨骼，也不进入个人肌肉力量计算。

### 训练记录

当前实现保存 `exercise`、`loadKg`、`repetitions`、`repsInReserve`（还能做几次）、`date`，以及本轮加入的四项自报字段：`variation`（动作变式，按所选动作给出可选项）、`range`（实际动作幅度，粗档选择）、`equipment`（器械类型）、`recordedAt`（本地 ISO 时间戳，用于同一日内的先后顺序）。

这四项**都是自报描述，不进入任何动力学计算**：动作变式与器械类型只作记录，预设动作仍只有每种一个示意轨迹；实际动作幅度是粗档自报，不是测得的关节角或杠铃行程。1RM 粗估池只纳入 `equipment` 为杠铃（或该字段缺失）的记录，哑铃、史密斯机、固定器械与自重记录的负荷不与杠铃公斤数互换，界面会注明“非杠铃器械不进入 1RM 粗估”。器械类型以“杠铃”为默认值，因此新表单与旧记录行为一致。若明确接近力竭（还能做约 0–2 次）且 `repetitions + repsInReserve ≤ 10`，界面采用 Epley 公式显示**动作级估算 1RM**，仅作粗略能力指标；不据此声称测出了单块肌肉质量。“3 次或更多”是下界，不能当作恰好 3 次计算点估计；不知道接近力竭程度的记录也不显示估算 1RM。旧版本保存的记录缺少这四项字段仍可读取与导入，导出时也保持原样。`npm run check:training-record` 核对字段校验、1RM 门槛、杠铃/非杠铃分流与备份往返。

训练记录列表默认只显示最近 5 条；列表上方另有**动作筛选**（全部动作／深蹲／卧推／实力举）、**搜索**（按动作、器械、变式、幅度、日期以及重量与次数的文本匹配）、**排序**（最近优先／重量优先／估算 1RM 优先）与**展开全部记录**四个控件，以及一行“共 N 条记录，当前显示 M 条”的说明。这些控件**只改变列表显示**：不写入本地存储（刷新后回到默认的“全部动作＋无搜索＋最近优先＋最近 5 条”）、不新增存储键、不改动已保存的记录，也不改变 1RM 粗估池与容量提示；筛选到的动作没有记录时显示“这个动作还没有记录。”，搜索没有命中时显示“没有匹配这条搜索的记录。”。按重量或估算 1RM 排序时，列表标题改为“重量优先”／“估算 1RM 优先”、展开按钮改为“只显示前 5 条”，不再自称“最近记录”；没有估算的记录（非杠铃器械）排在估算 1RM 排序的末尾。筛选下拉那一行的计数用的是该动作的记录总数，搜索只影响“当前显示”的那个数字。保存新记录会清空筛选与搜索（排序保持不变），导入备份则把三样都复位，以免刚存下或刚导入的记录被挡住。计数里显示的是记录条数本身（用户自己录入的行数），不是任何模型输出，因此不登记在[输出与置信登记](data/output_provenance.json) 里。

动作控制台另存三种动作各自的当前杠铃总重量，范围为 0–300 kg。该输入改变器械外观，并在“负重力学”视图进入杠铃重力的外力矩分量计算：按左右各承受一半重量和静态姿态，用 `M = (重量 × 9.80665 / 2) × 水平力臂`。深蹲只取矢状面；实力举取手腕到关节的水平距离。卧推使用单侧 OpenSim 参考轨迹，以三维位置矢量与假定手力计算 `|r × F|`。关节外力矩表没有加入人体自重、加速度、支撑反力或肌肉分担，所以既不是完整关节净力矩，也不是单肌肉力。深蹲另用输入体重、公开模型的体段质量比例和示意分段质心计算**全身加杠铃的静态重力作用线**与重力大小；未测足底压力中心、加速度和个体质量分布，手臂质量并入躯干近似。体脂与围度目前不改变这套质量比例。卧推“负重力学”研究层另外从单侧参考轨迹的手、肩、肘位置计算三组假定侧向手力下的三维杠铃外力矩大小；侧向力比例不是用户输入或测量值，仍未算出关节净力矩或肌肉发力。训练记录中的重量不会自动充当当前动作负重。若已有符合条件的训练记录，控制台显示当前重量相对于**已录入记录中最高动作级估算 1RM** 的比例；这仍不代表某块肌肉承受的力量。

手机动作控制台另外保存深蹲**模型幅度**选择（较浅 75°、原型默认约 96°、较深 117°）。这是用户选择的预设最深膝屈角，不是其真实关节角测量，也不会写入已有训练记录。所选幅度同步改变动作姿态、示意肌肉路径长度、杠铃重力力臂和全身静态重力线；OpenSim 实验参考层保持来源轨迹，不随这个教学控件变形。不同幅度的力板研究筛查仍不足以验证个人关节或肌肉力。

动作控制台可选每组动作周期 2.0、2.8 或 4.0 秒，默认 2.8 秒，并仅保存在本设备。它控制三种动作的预设动画播放速度；不是对使用者动作时长的测量。深蹲“负重力学”视图还按所选时长，对示意的全身加杠铃质心轨迹取 0.01 阶段间隔的二阶差分，显示 `F = (体重 + 杠铃质量) × (9.80665 + 竖直质心加速度)` 的**整体竖直支撑力情景**。该项状态为 `illustrative`，与静态重力线、杠铃单侧外力矩分开列出。没有个人实际姿态、速度、足底接触和负重位置；它不是实测地面反力、关节净力矩或肌肉力量。卧推和实力举没有对应动态力量估算。

公开 12 人自重深蹲对照还检查了“峰值膝屈与动作周期都由实验精确测出，再选最接近预设”的理想输入情形：整体竖直力只有 6/12 人的逐人误差优于固定默认，配对改善中位数为零；双力板压力中心也在动作中移动。因而这两个少量输入参数目前只控制教学情景，不能升级为 `estimated` 状态或驱动个人肌肉力高亮。实验方法见[动态深蹲验证数据](动态深蹲验证数据.md)。

## 输出字段及状态

每个数值输出附带 `status`：

- `input`：用户输入或由用户明确选择。
- `geometry`：由姿态与肌肉路径计算的几何量，例如路径长度；准确性仍依赖路径模型。
- `estimated`：由已标定动力学模型计算的估计量，需同时提供模型版本、条件和可信范围。
- `illustrative`：教学示意，不可用于力量结论。
- `unavailable`：尚未有可用模型或输入。

预期输出包括个人化骨骼与外表轮廓、各动作时间轴上的肌肉路径长度、关节角度、关节力矩、肌肉激活/力量估计，以及逐帧解释。**界面不可把 `illustrative` 或 `unavailable` 包装为实测结果。**

深蹲解剖研究层的八块网格（臀大肌、四块大腿、三块小腿）可选两种颜色：结构区分色，或按 OpenSim 模型肌肉肌腱路径相对站姿的长度比着色。后一模式以 ±2.5% 为蓝色变长／紫色变短／灰色近似不变的阈值，属于 `geometry`，不是网格表面应变、肌纤维长度、肌电、激活或力量。选中肌肉的金色提示仍只表示选择。实际发力色须由单独验证的动力学模型驱动，不能从长度色推断。

## 模型层次

1. **几何层**：体段长度、关节位置、外轮廓、肌肉表面和路径。
2. **质量层**：体段质量、质心、惯量及外部负重。
3. **功能层**：最大力量、肌腱与肌纤维参数、动作能力约束。

身高主要影响几何层，体重影响质量层；局部围度首先约束外轮廓。训练成绩首先约束功能层的**动作级能力**。不能把这些输入直接当成精确的单肌肉体积或生理参数。

当前动态示意骨架先按身高确定总高度，再用内侧腿长调整股骨与胫骨段比例，同时反向调整躯干段，保持站立头部位置不因腿长输入而改变。臂展扣除示意肩宽后，按固定比例分配给上臂和前臂。默认 175 cm 体型采用 80 cm 内侧腿长；当输入比例超过腿长系数 0.85–1.16 倍或臂展为身高的 0.88–1.12 倍范围时，页面显示实际采用值。这里的腿长与臂展是**骨架几何标定代理量**，不是测得的骨段长度。OpenSim 研究参考层仍只按身高统一缩放，不使用个人腿长或臂展。

上臂、大腿和小腿的示意圆截面半径由围度计算，腰部示意椭圆截面由腰围计算，胸肩与骨盆外形按人体比例过渡。未填写围度时，体重、体脂和身高形成简化外形先验。截面校验检查这些输入与数学轮廓的一致性，不等同于个体肌肉分割或肌肉量测量；后续须以真实人体测量数据校准。

卧推 OpenSim 参考层另有 101 帧、33 束单侧胸肩肌肉路径。四个肩、肘坐标的角度节点由人工手部轨迹拟合；输入的杠铃重量、体重、臂围和训练记录均未进入这组路径。界面中的百分比是相对推起端点的**肌肉肌腱路径长度变化**，显示的力臂是 OpenSim 关节坐标导数；两者都不是激活、收缩速度或肌肉力量。该层与“负重力学”中的杠铃外力矩目前没有动力学耦合。

卧推与实力举的三角肌前、中、后三束动态候选网格依据同源肱骨刚体和路径位移驱动；其网格不由臂围细分标定。显示在网格上的蓝／紫色取**整条模型肌肉肌腱路径长度比**，不取网格边长或肌纤维长度。几何筛查仍有约 6.9 cm 的最大路径表面差距，不能用此色判断肌肉主动收缩或发力。[Blender 与手机交叉核对](../blender/README.md)。
