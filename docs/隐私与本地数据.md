# 隐私与本地数据

这一页回答两个问题：**应用把你的数据放在哪里**，以及**它能连到哪里去**。结论由一个可复现的静态审计支撑：`scripts/audit_shipped_package.py` 读取发布包与当前网页构建，把事实写进 [包内审计](data/shipped_package_audit.json)，`npm run check:shipped-package-audit` 固定这些事实（权限一旦增加、出现未复核的网络调用或新的外部主机，检查就会失败）。

## 数据放在哪里

| 数据 | 存放位置 | 什么时候离开设备 |
| --- | --- | --- |
| 身体参数（身高、体重、体脂、围度、臂展、内侧腿长） | 本机 `localStorage`（键 `muscle-atlas-profile-v1`） | 只有你按「导出备份」时写出 JSON |
| 训练记录 | 本机 `localStorage`（`muscle-atlas-training-v1`） | 同上 |
| 当前动作、三个动作的当前杠铃重量、深蹲杠铃位置／幅度、动作周期、卧推节奏 | 本机 `localStorage`（另外六个键） | 不进入备份文件 |
| 参考数据、解剖模型、动作数据 | 安装包与离线缓存内 | 本来就随应用分发，不含你的数据 |

导出用的是系统分享／下载：文件由你选择保存位置或发送目标，应用不保留副本。导入会先校验字段，再在覆盖本机数据前向你确认。**没有账号、没有云同步、没有统计或广告 SDK**：网页包里没有第三方接口调用，也没有崩溃上报。

上表不是承诺而是**在真实浏览器里每次重跑的验收**（`npm run check:ui-data-flows`）：它填写身体参数并刷新确认留存、录入一条杠铃记录与一条哑铃记录（前者进入 1RM 粗估池、后者被排除）、走页面自己的下载路径导出备份，逐项核对导出文件**只有** `format`／`version`／`exportedAt`／`profile`／`training` 五个键（同时另存的动作选择等设置不得混进去），再清空本机存储、把同一份文件导入回来，确认参数与记录都恢复。

## 应用能连到哪里去

打包清单里只有两项权限：

- `android.permission.INTERNET`：Capacitor 的 WebView 通过本机 HTTPS 服务（`https://localhost`）加载安装包内的资源。应用代码里**唯一**的请求就是读取安装包自带的深蹲参考数据，没有任何远程接口。
- `com.muscleatlas.prototype.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`：AndroidX 库自己声明的私有权限，用来把动态注册的广播接收器限制在本应用内，不是系统敏感权限。

清单里**没有**存储、相机、麦克风、位置、通讯录、电话或身体传感器权限，也没有原生库（`nativeCode` 为空）。系统云备份是关闭的（`android:allowBackup="false"`），导出的文件通过不对外导出的 `FileProvider` 按次授权给目标应用。

源码里被审计到的网络／分享调用只有三处：一处读取安装包内 JSON（`/data/squat_opensim_reference.json`），两处是导出时的系统分享（Capacitor `Share.share` 与浏览器 `navigator.share`）。页面文字里出现的外部网址都是参考资料、数据来源与许可证链接，**只有你主动点击才会访问**；审计会逐一列出并分类，出现未归类的新主机就会让检查失败。

## 这个审计不是运行时保证

- 它是**静态审计**：读的是打包产物、清单与源码调用点，不能证明运行期 WebView 一次都没有打开过网络连接；真正断网、权限与分享行为的验收要在 Android 真机上做，目前**还没有做过**。备份导出／导入这条用户数据路径已在桌面无头浏览器里自动化（见上），但 Android 上走的是系统分享与系统文件选择，那一段仍只能在真机上验收。
- 被审计的产物是**调试签名包**（证书 `CN=Android Debug`），正式发布前必须重新审计签名与清单。
- 合并清单会引入库组件：当前有一个 AndroidX 组件对外导出，但它带 `android.permission.DUMP` 保护，只有系统签名持有者可调用；审计把它记录下来，而不是当作不存在。
- 外部主机只统计打包页面里出现的字符串，不等于对每条链接目标的内容审查。
- `localStorage` 只列出应用自己写入的键；系统、WebView 自身或其他应用的数据不在其中。
